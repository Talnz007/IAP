        ISLAMABAD AQI PREDICTOR - PROJECT CHALLENGES & MODEL SELECTION

PART 1: HURDLES AND CHALLENGES FACED
================================================================================

1. HOPSWORKS VERSION INCOMPATIBILITY
--------------------------------------------------------------------------------
   Problem: 
   - Error: "Client version 3.7.0 is not compatible with backend version 4.2.2"
   - The requirements.txt had "hopsworks>=3.0.0" which installed an older version
   
   Solution:
   - Changed to "hopsworks==4.2.*" to pin the compatible version
   - This ensured client-server version alignment

2. TARGET COLUMN NAME MISMATCH
--------------------------------------------------------------------------------
   Problem:
   - Error: "Target column 'aqi_target_24h' not found"
   - Training code expected 'aqi_target_24h' but Hopsworks had 'target_24h'
   
   Solution:
   - Updated all training code to use 'target_24h' as the target column
   - Modified train.py and training_pipeline.py accordingly

3. MISSING SOURCE FILES IN GIT
--------------------------------------------------------------------------------
   Problem:
   - Error: "ModuleNotFoundError: No module named 'src.training.models'"
   - The src/training/models/ directory was not tracked by Git
   
   Solution:
   - Added __init__.py and model files to Git tracking
   - Committed and pushed the missing files

4. GITHUB ACTIONS SECRETS CONFIGURATION
--------------------------------------------------------------------------------
   Problem:
   - Environment variables (API keys) not passing to GitHub Actions workflows
   - Pipelines failing due to missing credentials
   
   Solution:
   - Configured secrets in Repository Settings > Secrets and Variables > Actions
   - Added OPENWEATHERMAP_API_KEY and HOPSWORKS_API_KEY
   - Referenced them properly in workflow YAML files

5. STREAMLIT CLOUD MODEL LOADING ISSUES
--------------------------------------------------------------------------------
   Problem:
   - Webapp couldn't load models from Hopsworks on Streamlit Cloud
   - Authentication issues in serverless environment
   
   Solution:
   - Simplified webapp to use local model files committed to Git
   - Models are loaded directly from the models/ directory

6. NEURAL NETWORK DEPLOYMENT FAILURES
--------------------------------------------------------------------------------
   Problem:
   - TensorFlow models caused Streamlit Cloud to timeout
   - Deployment size increased by ~500MB due to TensorFlow
   - Cold start times were unacceptable
   
   Solution:
   - Replaced Neural Network with Random Forest
   - All models now use scikit-learn compatible .joblib format
   - Significantly reduced deployment size and load times

7. FEATURE MISMATCH BETWEEN TRAINING AND INFERENCE
--------------------------------------------------------------------------------
   Problem:
   - Model expected features in specific order during prediction
   - Real-time data had different column ordering
   
   Solution:
   - Store feature names in model metadata during training
   - Enforce correct feature ordering during inference


================================================================================
PART 2: WHY THESE THREE MODELS? (XGBoost, LightGBM, Random Forest)
================================================================================

MODEL 1: XGBOOST (Default/Recommended)
--------------------------------------------------------------------------------
Why Selected:
- Best overall RMSE performance (~25.3)
- Excellent at handling non-linear relationships in AQI data
- Built-in regularization makes it robust to outliers
- Fast inference time for real-time predictions
- Handles missing values automatically
- Industry standard for tabular data competitions

Performance: RMSE ~25.3 | R² = 0.89 | Training Time: 45s


MODEL 2: LIGHTGBM
--------------------------------------------------------------------------------
Why Selected:
- Extremely fast training (3x faster than XGBoost)
- Lower memory usage - important for cloud deployment
- Handles categorical features natively
- Competitive accuracy with XGBoost
- Ideal for hourly retraining scenarios
- Uses histogram-based algorithm for efficiency

Performance: RMSE ~26.1 | R² = 0.88 | Training Time: 15s


MODEL 3: RANDOM FOREST
--------------------------------------------------------------------------------
Why Selected:
- More interpretable than boosting methods
- Provides clear feature importance rankings
- Less prone to overfitting than boosting
- Stable and reliable predictions
- Good baseline model for comparison
- No complex hyperparameter tuning required

Performance: RMSE ~28.5 | R² = 0.85 | Training Time: 30s


================================================================================
MODELS WE DISCARDED AND WHY
================================================================================

1. NEURAL NETWORK
   - Deployment too complex (TensorFlow adds 500MB)
   - Overkill for tabular data with 160 features
   - No significant accuracy gain over XGBoost
   - Caused timeout issues on Streamlit Cloud

2. GRADIENT BOOSTING (Scikit-learn)
   - 5-10x slower than LightGBM for similar results
   - No GPU support
   - XGBoost/LightGBM are superior implementations

3. ELASTIC NET
   - Linear model cannot capture non-linear AQI patterns
   - Significantly higher RMSE (~45+)
   - Limited expressiveness for complex interactions

4. RIDGE REGRESSION
   - Kept as internal baseline only
   - Too simple for production use
   - Removed from UI to avoid user confusion


================================================================================
SUMMARY
================================================================================

The three selected models (XGBoost, LightGBM, Random Forest) represent the 
optimal balance between:

1. ACCURACY - All achieve R² > 0.85 for 24-hour predictions
2. SPEED - Fast enough for real-time inference (<2 seconds)
3. DEPLOYMENT - No heavy dependencies like TensorFlow
4. INTERPRETABILITY - Feature importance available for all
5. RELIABILITY - Stable predictions in production environment

This combination gives users flexibility to choose based on their priority:
- XGBoost: Best accuracy (recommended)
- LightGBM: Fastest training
- Random Forest: Most interpretable
